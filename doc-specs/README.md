# The specs of the book

The book in `docs/book` is written for people who use dampf; most of its pages are generated by
`/docs-gen` from the specs in this folder. A spec says what a page covers and which files are
true for it; the page is written from those files. This file describes how the folder is laid
out; how the pages are written is in [_styleguide.md](_styleguide.md).

## Three guides

The book has three guides, one per reader, each with its own sidebar
(`docs/book/.vitepress/config.mts`). A folder of specs belongs to one guide:

| Guide | Reader | Folder | Pages |
|---|---|---|---|
| **User guide** | a game programmer who writes C for the SNES and wants to compile it with dampf | `guide/` | what dampf is, getting started, writing C for dampf, writing fast C, the SNES hardware, compiling a whole game, debugging in Mesen |
| **Reference** | a user who wants everything about one subject | `reference/`, and the glossary | command line, the C subset, runtime and memory, the generated files, limits; later the hints |
| **Inside** | a technical reader who wants to know how dampf works under the hood | `inside/` | how a compile works, MIR, the optimizations, exact timing, testing, the roadmap |

## A spec and its page

`doc-specs/<folder>/<name>.spec.md` gives the page `docs/book/<folder>/<name>.md`. Its
frontmatter:

| Key | Meaning |
|---|---|
| `title` | the H1 of the page |
| `sources` | the files that are true for the page, glob patterns allowed; `BookSourcesTest` fails when one of them changed after the page was written |
| `audience` | the readers of the page, more closely than its guide says |
| `status: planned` | for a page of something not built yet: it is not generated |

Its body has the sections *Purpose*, *Sections* (one item per H2 of the page, in order), *Pay
attention to* and *Out of scope*. A generated page starts with the line
`<!-- GENERATED from doc-specs/... by /docs-gen. ... -->` and is never edited by hand.

Two pages have no spec and are written by hand: the home page (`index.md`) and the glossary
(`glossary.md`). Nothing regenerates them.

Files of this folder whose names start with `_` are not specs: `_styleguide.md`, and
`_sources.lock`, which `./gradlew stampBook` writes with the version of each source a page was
written from.

## Adding a page

1. Write the spec in the folder of its guide.
2. Add the page to that guide's sidebar in `docs/book/.vitepress/config.mts`.
3. Run `/docs-gen` for it, which writes the page and stamps its sources.

A spec of something not built yet gets `status: planned`; it stays out of the sidebar until the
line is removed and the page generated.

## Keeping the book current

The book is brought in step before a release, not with every change (ADR
[record 43](../docs/adr/0043-the-book-is-brought-in-step-before-a-release-not.md)); between
releases it may lag behind the code. `./gradlew checkBook` lists the generated pages whose spec
or sources changed after the page was written, and fails if there are any; it is not part of
`./gradlew build`. Before a release, run `/docs-gen stale` to regenerate those pages, or, when a
change does not touch what a page says, stamp it without regenerating:
`./gradlew stampBook -Pspecs=doc-specs/<page>.spec.md`.

In `docs/book`: `npm install` once, then `npm run docs:dev` serves the book locally and
`npm run docs:build` builds it and checks its links.
