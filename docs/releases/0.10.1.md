> This is still an alpha release. It works for me, that doesn't necessarily mean it works for you at the moment. Sorry 😔.

superdevkit is a development kit for SNES games written in C. You write a game once, and it builds as a ROM for the Super Nintendo, a program for Linux and Windows, and a page for the browser. It comes with dampf, its own C compiler for the SNES's 65816 CPU.

**[Play the example games in your browser](https://skerkewitz.github.io/superdevkit/example/)** · **[Read the book](https://skerkewitz.github.io/superdevkit/book/)**

## Download

| Your system | File |
| --- | --- |
| Windows (x64) | `superdevkit-0.10.1-windows-x64.zip` |
| Linux or WSL (x64) | `superdevkit-0.10.1-linux-x64.zip` |

Each zip brings its own Java, so you don't need to install one.

## Your first ROM

On Windows, in PowerShell, in the folder with the zip:

```powershell
Expand-Archive superdevkit-0.10.1-windows-x64.zip .
$env:Path = "$PWD\superdevkit-0.10.1\bin;$env:Path"
superdevkit init mygame
cd mygame
superdevkit build snes
```

On Linux or WSL:

```sh
unzip superdevkit-0.10.1-linux-x64.zip
export PATH="$PWD/superdevkit-0.10.1/bin:$PATH"
superdevkit init mygame
cd mygame
superdevkit build snes
```

The ROM is `build/snes/mygame.sfc`. [Getting started](https://skerkewitz.github.io/superdevkit/book/guide/getting-started) goes on from there.

## What each target needs

| Target | Command | You need |
| --- | --- | --- |
| SNES | `superdevkit build snes` | nothing else (an emulator such as MesenCE to play the ROM) |
| Windows | `superdevkit build win64` | Visual Studio with "Desktop development with C++" |
| Linux | `superdevkit build linux` | a C compiler and the OpenGL and X11 development libraries |
| Web | `superdevkit build web` | the Emscripten SDK, with `emcc` on the PATH |

## New in 0.10.1

The desktop and the web now draw every picture mode a game is likely to use. On the SNES nothing
changes: dampf, the code it generates and the kit's SNES library are the same as in 0.10.0, and
games written for 0.10.0 build and run as before.

### Picture modes on the desktop and the web

Rachael, the kit's PPU for the desktop and the web, draws more of what the SNES can show. Each
is the same as in Mesen, pixel for pixel:

- modes 0, 2, 3 and 4, with offsets per tile in modes 2 and 4 (a scroll for each column of tiles);
- 256-colour tiles for BG1 in modes 3 and 4, and direct colour;
- mosaic, on every layer;
- mode 7's second layer (EXTBG);
- `VMAIN`'s address remapping, and VRAM, CGRAM and OAM read back by DMA (`SDEVKIT_DMA_FROM_PPU`).

Until now, the desktop's check failed on these. It still fails on modes 5 and 6, on the high
resolution, overscan and interlace of `SETINI`, and on HDMA with indirect tables. They wait for a
game that needs them.

### The console API

`sdevkit/snes.h` has the names for them: `SDEVKIT_BG_MODE0`, `_MODE2`, `_MODE3` and `_MODE4`,
`SDEVKIT_OPT_BG1`, `_BG2` and `_VERTICAL` for offsets per tile, `SDEVKIT_MOSAIC()`,
`SDEVKIT_VMAIN_REMAP_2BPP`, `_4BPP` and `_8BPP`, and `SDEVKIT_SETINI_EXTBG`.

### 256-colour pictures

`superdevkit png tiles8` converts a PNG into tiles of 8 bits a pixel (64 bytes a tile) and a
palette of 256 colours, and `tiles8` is a new key in `superdevkit.toml`'s `[graphics]`.

### A new example

`examples/modes` shows each of the modes, one screen each. Like the other examples, it can be
[played in the browser](https://skerkewitz.github.io/superdevkit/example/).

## Known limits

- Music plays on the desktop and the web, but not yet on the SNES. Sound effects and save RAM work there.
- The kit has been tested in emulators, not on a real SNES.
- The C subset, the command line and the files dampf writes may change before 1.0.
- The games on the website need a keyboard.
